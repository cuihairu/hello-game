# 附录 A1. 游戏类型专题

这一组附录按常见游戏类型回看技术问题。它的价值不在于给品类下定义，而在于帮助读者快速回答一个更实际的问题：这类产品通常会把技术复杂度压在哪些地方。

按类型看问题有两个好处。第一，它更接近团队日常沟通，便于和策划、制作人、发行一起对齐。第二，它能帮助新人建立直觉，知道为什么同样叫“游戏服务端”，不同项目的难点会差这么多。

但品类不是架构结论。真正决定系统形态的，仍然是状态共享方式、时间推进方式、内容生产方式、运营节奏和商业约束。两个都叫 MMO 的项目，技术形态也可能天差地别；一个看起来像休闲游戏的产品，也可能因为强社交和高频活动而变得非常复杂。

这一章读完以后，应该能把下面几件事说清楚：

- 能从游戏类型快速联想到主导技术压力
- 能看出同一品类内部为什么会分化出完全不同的架构
- 能知道品类标签适合拿来做沟通，不适合拿来直接替代推导
