# 流控、背压与稳定性机制

《流控、背压与稳定性机制》讨论的是 执行模型 里的一个关键切面。它真正关心的不是定义本身，而是这个切面如何改变系统边界、团队协作方式和线上故障形态。

## 问题从哪里来

运行时问题通常不是“会不会多线程”，而是状态访问方式、调度单位和故障传播路径是否清楚。游戏系统里很多 bug 都来自时序和共享状态，而不是单点算法错误。

## 什么时候会变成主问题

单服对象数量增加、复杂逻辑增长、异步任务增多或线上尖峰流量出现时，执行模型的优劣会直接决定系统是否稳定。

## 常见方案与取舍

单线程串行最容易保证时序，Actor 和分区模型擅长隔离状态，协程利于表达异步流程，多线程适合并行重任务。真实系统往往是混合式，而不是二选一。 围绕“流控、背压与稳定性机制”做设计时，最好先明确目标链路、失败代价和观察指标，再决定复杂度应该放在哪一层。

## 常见误区

最常见的错误是为了性能过早并发化，结果共享状态和锁竞争把问题放大；或者在明明需要限流与背压时，只盯 CPU 利用率。 如果围绕“流控、背压与稳定性机制”的讨论只停留在概念名词，而不落到状态归属、版本窗口和恢复方式上，方案通常会流于表面。
