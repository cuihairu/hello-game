# 1. 总论与方法论

这一章负责建立判断框架，不直接替读者做技术选型，而是把游戏项目里最容易被混淆的几组问题拆开。重点不是工具名词，而是问题定义、约束识别和推导顺序。

这一章读完以后，应该能把下面几件事说清楚：

- 知道架构分析应从玩法和状态而不是从中间件开始
- 能区分生命周期阶段带来的不同工程重点
- 能把经验沉淀成可复用的判断框架
