# 10. 版本发布、配置与研发管线

这一章讨论的是长线游戏最容易被低估的一条主线：`功能不是写出来就结束了，而是要能被配置、被发布、被回滚、被协同维护`。

很多项目前期只盯着玩法开发，等内容变多、团队变大、版本变密之后，才发现真正拖垮效率的不是逻辑实现，而是：

- 版本边界不清楚
- 配置来源混乱
- 发布流程靠人工记忆
- 前后端改动无法协同落地
