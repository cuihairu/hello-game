# 4. 同步、战斗与实时交互

这一章讨论游戏里最容易把“玩法问题”逼成“架构问题”的那条主线：多端如何共享同一局战斗，局内时间如何推进，输入和状态如何收敛，客户端何时可以先播，服务端何时必须裁决，断线、追帧、回放和技能系统又如何建立在这套基础上。

对实时交互来说，最大的困难从来不是“服务器能不能算”，而是手感、公平性、可追责、可回放、反作弊、弱网容忍和工程复杂度不可能同时最优。同步体系真正做的，是在这些目标之间分配复杂度，并把代价变成可控工程事实。

## 本章文章

- [Tick 与时间推进](./01.md)：先把战斗时间、渲染时间、网络时间和逻辑时间拆开，明确同步体系的真实底座。
- [同步模型](./02.md)：建立状态同步、帧同步、锁步和混合方案的总览视角，先看问题空间，再谈具体实现。
- [帧同步详解](./03.md)：展开输入收集、延迟帧、帧包、默认输入、服务器协调、哈希校验和常见落地方案。
- [暂停、继续、追帧与断线重连](./04.md)：把战斗暂停、客户端挂起、服务器不停跑、追帧、快照恢复和加载策略放回同一条链路里讨论。
- [预测、补偿与纠正](./05.md)：说明客户端为什么要抢时间，以及服务端怎样把本地前馈重新收敛成权威结果。
- [确定性与数值一致性](./06.md)：讨论锁步、帧同步和回放体系为什么总会被浮点、随机、顺序和平台差异拖垮。
- [回放、观战与裁决](./07.md)：把输入日志、状态快照、观战延迟、仲裁证据和复盘工具统一进同步体系。
- [技能系统设计](./08.md)：从技能运行时骨架、效果管线、Buff、被动和同步边界出发，讨论战斗系统的内容组织方式。
