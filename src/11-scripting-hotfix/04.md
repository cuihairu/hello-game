# 热更新体系

热更新的本质不是“线上不用发版”，而是把一部分变化从高成本发布通道转移到低成本通道。

常见热更新对象包括：

- 资源
- 配置
- 脚本
- 部分宿主可插拔逻辑

热更新的收益很明显：

- 迭代更快
- 事故修复更快
- 平台审核压力更小

但风险同样明显：

- 版本组合暴增
- 新旧逻辑并存
- 回滚更复杂
- 线上问题更难复现

因此热更新系统必须先把这些问题考虑进去：

1. 更新对象的边界是什么
2. 热更后的状态如何切换
3. 是否允许中途替换正在运行的逻辑
4. 出问题后怎么回滚
5. 如何保证客户端、资源、配置、脚本之间的依赖关系

很多团队把热更新当成“效率神器”，最后却在事故处理时付出更大代价。真正成熟的热更新体系，不是更自由，而是更可控。
