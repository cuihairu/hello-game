# 关键问题清单

面对一个新项目，最值得反复检查的不是“用了哪些组件”，而是以下问题有没有提前回答。

### 玩法与交互

- 核心交互是离散还是连续
- 共享状态范围有多大
- 公平性和实时性要求有多高

### 服务与状态

- 哪些状态必须权威维护
- 谁拥有这些状态
- 异常退出时如何恢复

### 版本与内容生产

- 哪些变化靠代码发版
- 哪些变化靠配置和资源
- 新旧版本允许共存多久

### 运营与商业化

- 活动和商业化能力是否前置设计
- 埋点口径是否统一
- 经济和风控是否有观察面

### 稳定性与治理

- 有没有明确的观测面
- 有没有压测和容量认知
- 关键操作是否可审计

这类清单的价值，在于让团队别总在同一个地方重复犯错。
