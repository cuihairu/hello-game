# 2. 游戏类型与问题模型

这一章不是在给游戏重新分品类，而是在回答一个更有用的问题：`什么样的项目会把什么样的技术问题推到前台`。真正决定架构的，通常不是“它叫不叫 MMO”，而是共享状态有多强、时间推进有多连续、资产要不要长期沉淀、运营系统是不是产品核心。

如果不经过这一层抽象，团队很容易陷入两个极端：一种是只用品类名词讨论技术，最后所有 RPG 都被说成一个样；另一种是只看局部技术点，不再关心项目整体是什么问题结构。这两种看法都会导致方案选型失焦。

- [游戏类型的分类方法](./01.md)：说明为什么传统品类标签不足以指导技术设计，以及更有用的分类维度是什么。
- [单局房间型游戏问题模型](./02.md)：分析状态以“一局”为边界时，系统会怎样收敛成房间、匹配和结算问题。
- [强实时对战型游戏问题模型](./03.md)：讨论低延迟、公平性和反作弊如何共同塑造同步与裁决体系。
- [持续在线世界型游戏问题模型](./04.md)：解释世界状态持续存在时，为什么服务、数据和运维形态都会变重。
- [长周期成长与异步交互型游戏问题模型](./05.md)：讨论长期资产、离线收益和异步交互如何把数据库和配置系统推到前台。
- [经济与平台型游戏问题模型](./06.md)：分析交易、渠道、支付和生态能力成为主问题时，系统边界如何改变。
- [高频对象与重表现型游戏问题模型](./07.md)：解释对象数量、表现密度和资源吞吐为什么会同时压在客户端与服务端上。
- [模型之间如何组合](./08.md)：说明一个真实项目为何往往由多个模型叠加，而不是只属于单一类别。
