# 持续在线世界型游戏问题模型

持续在线世界型产品的核心特征是：`系统需要长期维护大规模、长生命周期、多人共享的在线状态`。

典型场景包括：

- MMORPG
- 大世界在线游戏
- 多场景持久世界
- 重社交重世界状态产品

核心问题通常是：

1. 世界如何分区、分片和迁移
2. 玩家如何跨场景移动和恢复状态
3. 世界状态和角色状态如何协同
4. 跨服关系如何建立
5. 运维、扩容、合服和长期治理如何承接

## 这类模型和房间模型的根本差异

房间模型天然有结束点，而持续在线世界通常没有明确“结束”。这意味着很多可以在房间制里靠局终结算解决的问题，在这里都必须变成长期在线治理问题。

这类项目不一定都强实时，但一定重状态管理和系统演化。它们往往会引入：

- 场景服 / 地图服 / 世界服的分层
- 在线状态与持久状态的分层
- 跨服中心、目录服务或控制平面
- 更复杂的服务路由和恢复策略

它们的难点往往在：

- 在线状态和持久状态如何一致
- 跨场景迁移时上下文如何完整交接
- 世界分区如何演进而不是一开始写死
- 多年运营后的历史数据和历史规则如何共存

这种模型的难点通常不在某一次战斗，而在系统如何长期活着。
