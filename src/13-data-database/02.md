# 关系型与非关系型数据库

关系型和非关系型的区别，不在于谁更高级，而在于数据约束和访问模式是否匹配。

### 关系型数据库

关系型数据库更适合：

- 结构稳定的数据
- 需要明确约束的数据
- 需要事务保证的数据
- 审计和对账要求高的数据

典型场景：

- 角色主档
- 订单
- 资产账本
- 交易记录

### 非关系型数据库

非关系型数据库更适合：

- 结构变化频繁的数据
- 高吞吐读写
- 大规模键值访问
- 对局部字段灵活性要求高的场景

典型场景：

- 在线状态
- 临时会话
- 缓存结果
- 部分大对象快照

但是“灵活”不代表“可以不建模”。很多项目一开始把所有复杂对象都塞进大 JSON，后面很快就会失去可维护性和可校验性。
