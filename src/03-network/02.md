# I/O 模型与事件通知机制

接入层面对的不是少量短连接，而是大量长连接和持续事件流。因此 I/O 模型会直接影响连接成本、延迟波动、线程利用率和故障隔离能力。这个话题虽然偏底层，但对上层体验有直接影响。

## 问题从哪里来

长连接系统里，真正稀缺的不是单次计算，而是对大量连接状态的稳定维护。线程一旦和连接强绑定，资源成本会迅速上升；事件分发和回调如果失去节制，又会导致背压失控和局部热点拖慢整条链路。

## 什么时候会变成主问题

在线人数上升、峰值登录风暴、消息推送密集和弱网重连频繁时，I/O 模型会从“实现细节”变成系统瓶颈。此时，事件循环、epoll/kqueue、连接写缓冲和限流策略是否设计清楚，会直接决定接入层能否稳定运行。

## 常见方案与取舍

事件驱动模型适合高连接密度场景，线程池适合承载较重业务处理，二者通常需要组合使用。接入层最好只做连接和协议相关工作，把重业务逻辑移出事件线程，这样才能避免局部慢请求拖垮全局。

## 常见误区

常见错误是把接入线程当万能执行器，结果任何慢逻辑都会引起全局写阻塞。另一类错误是只看平均吞吐，不看峰值抖动和写缓冲积压，最终线上问题表现为“偶发卡死”而不是持续高负载。
