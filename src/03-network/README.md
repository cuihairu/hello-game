# 3. 网络与接入协议

游戏项目里的网络问题，不是课本上的 TCP、UDP 选型题，而是线上主链路如何在真实网络环境里活下来。登录、匹配、局内输入、房间广播、聊天、活动通知、支付结果、资源下载都经过网络，但它们对时延、顺序、可靠性、重试和恢复的要求完全不同。只要把这些链路混在一起设计，系统就会在弱网、高峰和版本演进阶段不断暴露问题。

这一章要解决的，不是“网络怎么通信”这种泛问题，而是几类最常见的工程矛盾：

- 长连接会话怎样和业务会话解耦。
- 高实时消息和高可靠消息怎样分层。
- 接入层应该承担哪些职责，不应该承担哪些职责。
- 房间广播、弱网、切网、后台切前台和重连怎样成为常态设计。
- 协议如何在长期版本演进里保持兼容，而不是靠一次性约定。

游戏网络和普通 Web 请求的最大区别，不是“它也走 TCP 或 UDP”，而是它经常同时具备：

- 长连接与长期会话并存。
- 高频状态更新与低频控制消息并存。
- 强实时链路与强可靠链路并存。
- 弱网、切网、重连和广播风暴是日常场景，不是边缘故障。

所以网络层在游戏里不是透明底座，而是直接塑造同步、房间、恢复和线上稳定性的主链路基础设施。
