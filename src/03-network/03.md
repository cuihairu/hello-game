# 传输层与接入协议选择

TCP、UDP 和各种在其上封装的接入协议，并没有抽象意义上的胜负。真正的问题是：你的链路更怕延迟、丢包、乱序、带宽浪费，还是实现和运维复杂度失控。

## 问题从哪里来

不同消息的语义完全不同。登录鉴权、支付回调、角色资产变更更看重可靠性；局内位移、朝向、技能输入更看重时效性；聊天和通知则通常可以接受较大延迟。传输层选择本质上是在这些语义之间做映射。

## 什么时候会变成主问题

当项目要同时承载高频交互和强一致业务，或者要适配复杂移动网络环境时，传输层的选择就会影响后续同步与补偿设计。很多同步问题其实是协议层没有把“应该可靠”和“应该及时”区分开。

## 常见方案与取舍

TCP 简化了可靠性处理，适合大量控制类消息；UDP 更有利于低延迟和自定义语义，但需要团队自行处理丢包、重传和顺序问题。很多项目会采用混合方案，或者在 UDP 上封装自己的可靠层。关键不是追求时髦，而是明确团队是否有能力长期维护这套语义。

## 常见误区

常见误区包括把 UDP 神化成“天然低延迟万能解”，或者把 TCP 视为“足够好所以什么都能做”。忽略消息语义差异，最后只能在业务层反复打补丁。
