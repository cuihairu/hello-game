# 16. 可观测性、性能、容量与稳定性

上线之后，系统真正暴露出的不是设计图，而是运行行为。日志、指标、Tracing、Profiling、压测和稳定性治理，都是把这种运行行为转成可理解、可定位、可决策的信息。没有这层能力，团队只能靠经验和猜测处理线上问题。

这一章关心的不是“监控平台怎么搭”，而是如何围绕游戏主链路建立观测视角：登录、匹配、房间、战斗、结算、活动和支付这些流程，应该留下哪些证据，出现抖动时靠什么迅速缩小问题面。
