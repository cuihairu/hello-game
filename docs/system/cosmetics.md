# 外观、皮肤与装扮

## Category

system / 玩法系统（商业化外观件）。节点定位：外观系统把「不影响数值的装扮内容」变成「可获取、可持有、可装备、可展示」的对象——内容分型、拥有关系、装备解析、展示与隐藏四件事。它是弱数值付费的主战场，资产侧（模型/贴图/特效）在 art 树，购买与抽奖入口在[结算](./settlement.md)与[掉落与概率设计](/numerical/05)，本页只管外观对象本身的机制。

## Definition

外观是**不含战斗数值**的表现内容：皮肤（整套外观替换）、装扮件（可混搭的散件）、称号（文本徽记）、头像框、载入画、动作/特效。它的关键契约是「不影响平衡」——一旦外观带数值，它就从商业化内容变成付费变强，红线被跨过。共同结构：**内容定义 + 拥有关系 + 装备位（可多槽）+ 展示规则**。

## Problem

外观的坑按出现顺序：

- **外观带数值**：为卖皮肤顺手加属性，外观变成功利选择，玩家「为强度买皮肤」而非为喜好——红线破防，长期反噬口碑。
- **拥有与装备混淆**：把「拥有整容」和「当前装备」存成一处，换皮肤等于失去旧的；或装备了不拥有的外观。
- **多槽位冲突**：皮肤是整套、装扮件是散件，两者叠加的优先级与互斥没定义，出现「穿了皮肤又戴散件」的穿模或覆盖事故。
- **限时外观回收口径**：租用型外观（限时体验）到期收回，与「买断」混在一处存储，到期误删买断内容。
- **资产与逻辑耦合**：外观资源包名写死在客户端逻辑里，加一套皮肤要改客户端发版——外观是更新最频繁的内容，必须数据驱动。

## Algorithm

### 内容分型：按装备槽与互斥关系建模

```text
appearance_def:                    # 静态表，美术与策划维护
  id:         skin-knight-a        # 整套皮肤
  slot:       skin                 # skin / headgear / weapon_fx / title / frame / loading
  group:      knight_family        # 互斥组：同组内二选一
  numeric:    none                 # 契约字段：外观不得带数值（表侧校验）
  asset_key:  knight_a             # 资源键，客户端据此加载，逻辑不写死包名
  source:     gacha / shop / event / achievement

owned_appearance:                  # 拥有关系，独立于装备
  player:     u1001
  id:         skin-knight-a
  acquired_at: 2026-10-01
  kind:       permanent            # permanent / rental
  expire_at:  null                 # rental 才有

equipped_appearance:               # 每槽位一条
  player:     u1001
  slot:       skin    → skin-knight-a
  slot:       title   → title-firstclear
```

- **拥有与装备分离**：`owned` 是资产、`equipped` 是指针——换装不动资产，租用到期只影响 `equipped` 的合法性判定，不误删买断内容
- `numeric: none` 是表侧校验字段：外观定义表不允许出现数值列，从数据层保证「不影响平衡」契约
- 互斥用 `group` 表达：整套皮肤与散件、同部位散件之间的覆盖规则在装备解析时按 group 优先级裁决

### 装备解析：服务端权威 + 客户端表现

- 服务端只存「哪些槽位装了哪个 id」，不存外观的渲染结果——表现全在客户端
- 装备动作**校验拥有关系**：装一个不拥有的 id 直接拒绝，客户端上报的装备请求不信任
- 互斥解析在客户端做（同一套 group 表），服务端只保证「装上的都是拥有的」——表现层的穿模/优先级属客户端实现，服务端不裁决
- 其他玩家看到你的外观：外观数据随玩家实体同步（进视野时带装备快照），[AOI](/server/aoi) 与实体同步的口径见 server 树

### 获取与展示：多入口、弱数值、可炫耀

| 入口 | 形态 | 说明 |
|------|------|------|
| 商店直购 | 买断 | 明码标价，走支付凭证 |
| 抽奖 | 随机获取 | 概率与保底见[掉落与概率设计](/numerical/05) |
| 活动/成就 | 条件解锁 | 作为进度奖励，联动[成就与图鉴](./achievement.md) |
| 限时租用 | 体验后转购 | 到期收回 `equipped`，不收回买断 |
| 战令轨 | 赛季限定 | 联动[战令与赛季轨](./battle-pass.md) |

- 展示面的「炫耀」要克制：全服广播「某玩家获得稀有皮肤」是拉动需求的杠杆，但滥用见[走马灯与公告](./marquee.md)的限流口径——**可配置阈值**，不是每次获取都广播
- 限时/限定外观的稀缺性靠**获取窗口**而非事后删改：过期后不返场是运营承诺，返场要慎重（承诺破坏的代价大于短期收入）

### 与数值侧的红线

- 外观系统与[战斗数值与伤害公式族](/numerical/02)必须**零耦合**：外观 id 不出现在任何伤害、属性或战力计算里
- 「外观是否影响手感」的边界（如武器皮肤的换弹动画）属客户端表现，但不得改变判定帧或命中判定——表现与逻辑分离由 client 树承接
- 队友/敌方辨识度：外观自由混搭可能影响战场识别（敌对阵营的皮肤识别），部分品类用「队友/敌人统一外观」选项或竞技模式限制外观，这是品类级口径

## Used By

- **英雄联盟 / 王者荣耀**（商业 MOBA）：皮肤为核心商业化内容，纯表现不涉及数值；限定与至臻等档位靠获取窗口与稀有度分层——「外观不卖强度」的商业实践参照。
- **CS2 / Dota 2**（商业竞技，Valve 公开资料）：饰品系统（武器皮肤、信使、至宝）是 UGC 与交易市场化的外观参照，稀有度与磨损等非数值属性驱动价值。
- **Fortnite**（商业大逃杀）：皮肤 + 限时返场 + 联动 IP 的运营形态，本赛季为外观商业化最活跃的公开参照。
- **原神 / 崩坏：星穹铁道**（商业手游）：角色皮肤与名片、头像框等轻量装扮，是「重内容 + 轻装扮」的参照。
- **平台侧**：Steam 社区市场的外部交易以公开市场规则为准，本页只引站内拥有/装备口径。

可参考分析：LOL/王者皮肤=可参考（外观不卖强度的红线与档位分层落与数值侧的红线一节）；CS2/Dota 饰品=可借鉴（非数值属性驱动价值，落稀缺性设计，外部交易本仓不展开）；Fortnite 联动返场=可借鉴（获取窗口与返场慎重，落获取与展示）；原神轻装扮=可参考（头像框/名片类轻量槽位落内容分型）。

## Related

关系链：内容分型 → 拥有与装备分离 → 装备解析 → 获取与展示。逐段回答「为什么需要下一个」：

- 分型定了槽位与互斥，才谈拥有——没有槽位模型，混搭无从裁决。
- 拥有与装备分开了，换装才不丢资产——租用到期只动装备不动买断。
- 装备解析服务端权威了，展示才可信——不拥有的装不上，同步给他人时才有公信力。
- 获取入口散了才要红线——外观越多入口、越接近商业化，越要守住「不卖强度」。
