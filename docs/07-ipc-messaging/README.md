# 7. 消息系统与进程间通信

系统一旦从单进程走向多进程、多线程、多服务，通信问题就不会再是“怎么把数据发过去”这么简单。真正的难点是：哪些链路必须同步拿结果，哪些链路可以异步放手，哪些消息允许重复，哪些消息必须保序，哪些链路一旦积压就会把主系统拖死。

消息系统在游戏工程里经常被两种方式误用。一种是把它当成万能总线，什么请求都想丢进队列；另一种是把它只当成外围工具，低估了事件驱动在削峰、解耦和跨系统协作上的价值。前一种会把主链路做得不可解释，后一种会让系统长期背着大量同步耦合。

这一章讨论的不是某个 MQ 产品，而是消息与 IPC 在工程上的边界问题：什么时候该直接调用，什么时候该走异步事件，为什么主链路和外围链路的通信语义不能混用，延迟、吞吐、顺序和幂等为什么永远在互相拉扯，以及团队到底应该按什么问题去选通信方案。
