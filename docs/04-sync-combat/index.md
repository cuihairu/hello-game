# 4. 同步、战斗与实时交互

这一章讨论的是游戏里最容易把玩法问题逼成架构问题的那条主线：多端怎样共享同一局战斗，局内时间怎样推进，输入和状态怎样收敛，客户端何时可以先播，服务端何时必须裁决，断线、追帧、回放和技能系统又怎样建立在同一套时序规则上。

实时交互真正困难的地方，从来不是“服务器能不能算”，而是下面这些目标不可能同时最优：

- 手感要快。
- 公平性要站得住。
- 结果要可追责。
- 弱网要能容忍。
- 回放和观战要能重建。
- 工程复杂度又不能失控。

同步体系真正做的，不是选择一个时髦方案，而是在这些目标之间分配复杂度，并把代价变成可控的工程事实。

这一章的阅读顺序也有明确逻辑：

- 先把时间推进讲清楚，因为同步问题往往先是时间模型问题。
- 再讲同步模型，因为裁决权和一致性时机决定后续所有系统。
- 然后展开帧同步、暂停恢复、预测补偿和确定性这些最容易互相牵连的部分。
- 最后把回放、观战、技能系统放回同一条链路，说明它们为什么不是后补功能。
