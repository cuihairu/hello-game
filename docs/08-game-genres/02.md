# 强实时对战

强实时对战的关键词不是“PVP”，而是玩家操作之间的时间差足够小，以至于延迟、抖动、丢包和作弊都会直接影响公平性和手感。MOBA、FPS、格斗、竞速、体育对抗都可能落在这个范围内，只是同步方式不同。

## 这类游戏真正难在哪里

这类产品最难的不是把规则写出来，而是让所有玩家看到“足够一致、足够及时、又不容易被作弊利用”的世界。这里的核心矛盾非常硬：

- 玩家希望本地反馈立刻发生
- 系统需要服务端权威来保证公平
- 网络天然存在延迟和丢包

这三件事不能同时完美满足，所以强实时项目一定是取舍艺术，而不是单一技术选型问题。

## 架构重点通常放在哪

- 同步模型是第一决策：锁步、状态同步、帧同步、服务器权威模拟，各自影响引擎、战斗设计和调试工具。
- 网络链路是主玩法一部分：弱网策略、插值、预测、回滚、补包，不是外围优化，而是核心体验。
- 反作弊必须前置：客户端越重、结算越晚、权威越弱，作弊空间越大。
- 观战、回放、仲裁往往不是附属功能：它们反过来决定你能不能定位线上问题和处理争议。

## 常见方案与取舍

服务端权威模拟是更稳妥的主流路线，因为它更容易处理公平性和作弊问题，但代价是服务端成本更高，战斗逻辑、工具链和回放体系都要更重。

如果采用帧同步或更接近锁步的方案，优点是带宽相对可控、客户端表现一致性更高，缺点是对客户端 determinism、版本一致性和弱网容忍要求很苛刻。只要有一个环节不稳，线上就会出现漂移、分叉和难以复现的 Bug。

## 常见误区

- 只盯平均延迟，不看抖动和长尾。玩家骂“手感烂”时，往往不是因为均值高，而是因为不稳定。
- 先把战斗做出来，再补同步和反作弊。通常补不上，只能推翻重来。
- 把弱网优化当客户端细节。实际上它会影响技能设计、碰撞策略、命中判定甚至数值平衡。
