# 注册中心、负载均衡与一致性哈希

《注册中心、负载均衡与一致性哈希》讨论的是 缓存与中间件 里的一个关键切面。它真正关心的不是定义本身，而是这个切面如何改变系统边界、团队协作方式和线上故障形态。

## 问题从哪里来

基础设施之所以危险，是因为它们看起来通用、接入快，但一旦被放进主链路，其故障模式会被业务放大。

## 什么时候会变成主问题

热点读写、跨服务协作、资源分发和弹性扩缩容时，中间件会成为性能和稳定性关键点。

## 常见方案与取舍

常见做法是把缓存用于热点与派生结果，把 MQ 用于异步协作，把注册与负载均衡用于路由治理，把对象存储和 CDN 用于静态资源分发。每一项都应有失效策略。 围绕“注册中心、负载均衡与一致性哈希”做设计时，最好先明确目标链路、失败代价和观察指标，再决定复杂度应该放在哪一层。

## 常见误区

最常见的错误是把缓存当权威源、把注册中心当配置中心替代品，或者忽视对象存储和 CDN 的版本与权限治理。 如果围绕“注册中心、负载均衡与一致性哈希”的讨论只停留在概念名词，而不落到状态归属、版本窗口和恢复方式上，方案通常会流于表面。
