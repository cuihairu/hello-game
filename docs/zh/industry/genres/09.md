# Roguelike 与 Roguelite：定义、柏林解释与设计模式

## Category

industry / genres 子树。节点定位：Roguelike 深读——什么让一款游戏成为 roguelike、柏林解释的标志性特征、roguelite 的分化，以及让跑局制游戏成立的设计模式。

## Definition

**Roguelike** 一词为在机制上继承《Rogue》（1980）DNA 的游戏而造。权威定义是**柏林解释**（2008），起草于国际 Roguelike 开发会议。它同时列出“高价值”因素（按其自身表述为必须）与“低价值”因素（常见但不构成定义）。

按柏林解释，高价值因素如下：

1. **随机环境生成**——游戏世界随机生成以提升重玩性；物品外观与位置随机，怪物外观固定但位置随机。
2. **永久死亡**——你不该指望第一个角色通关；死亡后从第一层重来（可以有存档，但读档即删除）。
3. **回合制**——每条指令对应一次行动/移动；游戏对时间不敏感，可以慢慢想。
4. **网格制**——世界是均匀的瓦片网格；怪物与玩家无论体型各占一格。
5. **非模态**——移动、战斗等所有行动发生在同一模式下；任何行动在任何时刻都可用。
6. **复杂性**——足够的复杂度，让常见目标存在多种解法。
7. **玩家对世界**——不存在怪物间关系；玩家是唯一的主动者。
8. **对称性**——适用于玩家的规则同样适用于怪物：它们有物品栏，会用道具、施法。
9. **ASCII 显示**——传统显示用 ASCII 字符表现瓦片世界。

低价值因素（常见但非必需）：生命值、等级成长、物品鉴定、饥饿/消耗等。

## Roguelite: The Split

现代用法区分两者：

| | Roguelike（柏林） | Roguelite |
| --- | --- | --- |
| 永久死亡 | 整局重置 | 整局重置 |
| 局外成长 | 无（或极少） | **跑局之间持久解锁** |
| 跑局结构 | 一局 = 整个游戏 | 一局 = 一次尝试；解锁持续累积 |
| 代表作 | Rogue、NetHack、Angband、Brogue | 《死亡细胞》《Hades》《杀戮尖塔》《Spelunky》 |

roguelite 的分化加入了一层**局外成长**（解锁、图鉴、meta 货币），同时保留局内永久死亡。这是商业意义最大的一次改写——它保留了永久死亡的张力，又给玩家跨失败的、不挫败的进度感。

Cloudfall Studios 的分析把两个不可再减的特征重构为**程序化内容**（每局随机生成）与**永久选择**（Permachoice，结果不可撤销，包括死亡）。用“永久选择”而非“永久死亡”，是有意允许局外成长——只要那些决定同样不可撤销。这个框架对现代 roguelite 更干净。

## Why Permadeath Works

永久死亡重新定义了失败状态。玩家不再是“通关然后重打失败的地方”，而是被期待不死完成整局。死亡不是暂时的挫折，而是**游玩循环的一部分**：绝大多数尝试以死亡告终，“你输了”读起来是“带着学到的东西再来一次”。

设计上的收益：

- **切实的赌注**——没有读档没有命数，每个决定都有分量；险境令人心跳加速。
- **重复本身就是设计**——游戏为多次尝试而生，重开不像检查点游戏那样沉重。
- **从失败中学习**——每一局都让下一局更深，而不只是重复。

对应的风险：如果游戏因*游戏本身*的错误（不公平生成的必输地图）而非玩家的错误惩罚玩家，永久死亡读起来就是残忍。最好的 roguelike 让玩家在打错时感到被惩罚，而不是生成器背叛他们时。

## Procedural Generation as the Engine of Replayability

程序生成意味着关卡不是硬编码的——而是每局从模板加随机化生成。玩家无法背版，每次游玩都是对新空间的探索；*形式*稳定（地牢总是房间加走廊），*具体排布*变化。

两个设计收益：

1. **重玩性**——每次的场地都不同；玩家适应的是底层模式，而非背下一个具体布局。
2. **盲探索**——不用记“下扇门后面是什么”，但你会形成“可能是什么”的感觉。

危险在于：随机性过大会让难度剧烈波动，产生必输局或无聊局。把生成器校准到每张地图都好玩且可通关，是真正的工程量——这正是 roguelike 的架构枢纽（见设计模式一节）。

## The Architecture-Side View: What a Roguelike Demands

从 genre-coverage 对照表看，Roguelike 品类最先要求这些特性组件：

- **随机种子与可复现**——确定性 RNG，跑局可重放、可加种子、可审计。
- **局内 / 局外状态分离**——跑局状态（死亡即重置）与 meta 状态（持久）。
- **解锁与图鉴**——局外成长层。

主导的问题模型是**房间制会话**（每局是一个会话）与**长周期成长**（meta 层）的组合。

对服务端而言，roguelike 的架构问题是：

- **RNG 放在哪里？**要求是确定性、有种子、可复现——同一颗种子必须产出同一局，因此种子是跑局记录的一部分。
- **什么重置、什么持久？**局内状态（背包、HP、地图）重置；局外状态（解锁、图鉴、货币）持久。边界必须显式。
- **跑局结果是否权威？**单人跑局客户端可以持有状态，但任何竞技或共享元素（每日挑战、排行榜、加种子跑局）必须服务端权威，且种子由服务端下发。
- **跑局反作弊**——跑局参与排名时，种子 + 结果必须能在服务端校验。

## Design Patterns That Make Run-Based Games Work

这些是商业上成功的 roguelike/roguelite 反复出现的模式：

| 模式 | 作用 | 例子 |
| --- | --- | --- |
| 加种子 RNG | 确定性、可审计的随机 | 所有柏林式 roguelike |
| 保底 / 连败打断 | N 次失败后必得稀有掉落 | 现代带掉落的跑局 |
| 局外解锁经济 | 跨死亡持久的货币/物品 | 《Hades》《死亡细胞》 |
| 构筑多样性 | 每局存在多个可行构筑 | 《杀戮尖塔》《以撒的结合》 |
| 公平但未知的信息 | 给足决策信息，留足惊喜 | 战争迷雾、物品鉴定 |
| 跑局时长设计 | 单局长度适中且有自然终点 | 20–40 分钟一局，而非无限 |
| 容错机制 | 缓解倒霉死亡的机制（复活、怜悯） | 许多现代 roguelite |
| 每日 / 加种子挑战 | 全员同一颗种子，排行榜 | 《杀戮尖塔》每日挑战 |

需要工程化处理的张力：**难度方差**。跑局制游戏的生死在于死亡究竟是玩家的错还是生成器的错。保底、容错和公平信息系统都在把答案推向前者。
