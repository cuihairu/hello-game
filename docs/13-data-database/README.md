# 11. 数据建模与数据库

数据问题在游戏项目里从来不只是“选 MySQL 还是 NoSQL”。真正决定系统稳定性的，是状态到底如何被划分、谁是权威数据源、哪些数据必须能恢复和审计、哪些数据只是高性能副本，以及当项目进入长线运营、合服迁移和资产复杂化之后，这套数据结构还能不能继续支撑演进。

很多团队早期把数据库理解成单纯的持久化底座，等到后期才发现问题集中爆发：

- 高实时状态和长期资产混在一起
- 查询方便和权威一致性互相冲突
- 数据一旦写坏，回滚和审计没有抓手
- 合服、迁移、归档和补偿时找不到单一真相源

这一章讨论的不是数据库产品功能表，而是数据作为系统边界的核心对象，应该如何被分类、建模、存储、迁移和恢复。
