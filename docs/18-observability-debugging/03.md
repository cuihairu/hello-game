# Profiling、火焰图与热点分析

性能问题如果只靠经验猜，很容易在错误方向上花掉大量时间。Profiling 和火焰图的价值，不在于展示一个酷炫图形，而在于把“感觉这里慢”变成“这段路径在某个负载下确实最贵”。

## 问题从哪里来

游戏服务和客户端都存在复杂热点：某些 Tick 帧突然拉长、某类对象更新异常昂贵、某个序列化路径在广播时占满 CPU、某个资源加载链路拖垮首屏。没有实际采样和调用栈证据，团队很容易把优化做在最显眼却不最关键的地方。

## 什么时候会变成主问题

性能压力上升、线上出现抖动尖峰、版本更替引入未知回退或容量预估偏差时，热点分析就会成为关键手段。尤其在无法稳定复现的场景下，线上采样能力往往比本地调试更重要。

## 常见方案与取舍

常见做法包括离线 Profiling、线上低开销采样、火焰图分析和针对特定模块的自定义计时。关键是采样结果要能和业务上下文关联，例如某个热点发生在什么地图、什么玩法、多少对象数量下。

## 常见误区

最常见的误区，是拿一张火焰图就开始下结论，不看采样环境和业务上下文。另一类误区，是把 Profiling 当成专项优化时才开启的工具，而不是常规性能治理的一部分。
