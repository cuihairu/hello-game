# 专项可观测与 Tick 指标

通用 CPU、内存和接口耗时指标，只能告诉你机器是不是忙，不能告诉你这局游戏为什么卡、为什么某个房间经常重连、为什么某类技能在高峰期争议变多。游戏系统必须有围绕主链路设计的专项可观测。

## 问题从哪里来

游戏体验高度依赖逻辑节奏。只看系统层指标，会漏掉很多真正决定玩家感知的信号，例如 Tick 漂移、房间广播积压、匹配耗时分布、重连恢复成功率、结算延迟和活动规则命中异常。没有这些指标，线上问题就只能停留在笼统的“服务器有点卡”。

## 什么时候会变成主问题

实时房间、持续在线世界、复杂活动系统和高频版本迭代，都会让专项指标成为第一手证据。越是长线项目，越不能只依赖底层基础设施监控。

## 常见方案与取舍

专项可观测的做法通常是围绕登录、匹配、房间、战斗、结算、支付和活动等主流程建立黄金路径指标，再为 Tick、对象数、队列积压、广播耗时和重连恢复设计细粒度观测。代价是埋点和指标治理成本会上升，但换来的是对业务链路真正有用的可见性。

## 常见误区

最常见的误区，是把专项指标当成补充装饰，直到线上出了体验问题才临时加日志。另一类误区，是指标过多却没有分层，最后告警很多，但没人知道哪些告警真正影响玩家。
