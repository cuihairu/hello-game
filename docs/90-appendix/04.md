# 如何使用附录

附录最容易出现的两种命运，一是被当成正文重新读一遍，二是买椟还珠式地只翻附录不碰主线。这两种用法都没有理解附录与主线的分工。这一页说明附录在整个知识库里扮演的角色、适合的使用时机，以及什么时候应该从附录退回主线。

## 附录与主线的分工

知识库主线由总论、问题模型起步，依次展开网络接入、同步与战斗、执行模型、服务拆分、消息与 IPC、客户端架构、脚本与热更新、版本发布、数据建模、缓存与中间件、通用服务、运营与商业化、平台与 SDK、可观测性、安全与风控，最后落在实践与复盘。主线的工作是建立因果：每一章解释一类问题为什么长成那样，约束从哪里来，取舍如何推导。

附录则由游戏类型专题、问题域归纳、配置管线、容量扩缩、引擎语言工具几部分组成，工作方式完全不同：

- 不重新推导，只压缩：把散在多章的内容按同一视角重新排列。
- 不建立理解，只服务回看：前提是读者已经拥有主线建立的理解框架。
- 不提供答案，只提供对照：结论都带着各自的前提条件。

一个简单的比喻：主线是路，附录是地图。地图可以反复看，但地图替代不了走路。

## 什么时候翻附录

附录的使用时机有相当清晰的信号，通常是手里已经有一个具体问题：

- 要做一个选型或方案对比，需要一组稳定的维度来组织讨论。
- 要评估一个项目或竞品，想快速确认这类产品的技术压力分布。
- 要准备评审、分享或培训，需要把散落的内容组织成材料。
- 复盘时想确认，同类问题在别的项目里是怎么发生和被处理的。
- 读主线读到一半，想先看看整体地图再决定细读的顺序。

反之，如果没有具体问题，只是想“学习一下”，附录通常不是正确的起点。压缩过的事实缺乏因果支撑，读起来轻松，留下来的是错觉。

## 带着问题回看

带问题回看是最常见的用法，操作上有几点值得注意：

- 问题先写成一句话，越具体越好：“结算链路权威怎么定”远好于“看看房间制”。
- 回看时先扫这页的结构，找到与自己问题对应的小节，而不是从头读到尾。
- 小节里出现看不懂的结论时，标记下来，这是需要回主线补因果的位置。
- 回看的结果最好落成几行笔记，写清这个问题在书里的答案链路。

回看的产出物是笔记而不是“看过了”的感觉。附录页本身是别人的压缩，只有加上自己项目的上下文，它才会变成可复用的东西。

## 做事前的横向对照

对照是附录的第二种主要用法，常见于选型会和方案评审前：

- 按品类或问题域定位，取出相关页做背景阅读。
- 把自己项目在各维度上的情况填进对照框架，允许填未知。
- 对照结果直接带入会议，作为讨论的起点而不是终点。

事前对照和临场发挥的差别很明显：前者让会议聚焦在维度分歧上，后者让会议在各自记忆里打转。附录在这件事上的价值，就是把“记忆”换成“纸面”。

## 组织分享与培训材料

附录天然的横向视角很适合二次利用：

- 做内部分享时，取一个专题页做骨架，往里填自己项目的实例和数据。
- 带新人时，先给专题页建立地图，再指定主线里的对应章节细读。
- 做评审模板时，从问题域归纳里挑选与项目相关的约束，整理成评审问题清单。
- 复盘归档时，用专题页核对同类项目的常见坑，确认改进项没有漏掉方向。

这类用法的共同点，是附录提供结构、使用者提供血肉。只用附录不做填充，材料会显得空泛；只用实例不做结构，材料又散乱难传。

## 判断自己该读哪里

在主线和附录之间选择，可以依赖几个简单的自检问题：

- 说得出问题但说不清因果：回主线，读对应章节的推导。
- 说得清因果但需要横向视野：查附录，用压缩后的视角组织材料。
- 连问题的轮廓都还没有：从问题模型入手，先确定主导问题域，再决定走向。
- 发现附录结论与项目实际观察冲突：回主线核对前提，差异往往就在前提里。

这套自检的底层原则只有一条：理解在主线，索引在附录，两头都要有，缺哪头就往哪头走。

## 团队层面的使用约定

附录要在团队里持续发挥作用，通常需要一点约定：

- 统一词汇：讨论时按知识库的问题域词汇说话，减少各说各话。
- 材料挂钩：评审模板和复盘模板里直接引用对应的专题视角，让附录进入工作流。
- 新人路径固定：先主线后专题的顺序写进入职材料，避免新人只在附录里打转。
- 定期回填：项目自己的经验和数据回填到团队的对照表和清单里，附录之外长出项目资产。

附录是通用的，团队资产是自己的。两者接起来，知识库才会从阅读材料变成工作底座。

## 附录不能替代的事

最后是几件附录明确做不了的事：

- 替代主线的理解：标签记不住约束，约束记不住才会在评审时漏问。
- 替代项目的具体推演：容量、权威、发布这些判断，最终都要落到自己项目的数字和场景上。
- 替代真实经历：读过一百个案例和扛过一次故障，仍然是两种能力。

附录的诚实定位是加速器：加速回看、加速对照、加速组织材料。它加速的前提是主干已经存在，主干不存在时，加速器只能让人更快地跑偏。

## 常见误区

- 只看附录不看主线，积累了一堆标签化印象，无法支撑实际决策。
- 把附录当入门教材，在压缩过的事实上强行建立理解。
- 回看不带具体问题，读完只留下模糊印象，没有可复用的产出。
- 用附录结论跳过自己项目的推演，把通用对照当成了项目答案。
- 团队里没有使用约定，附录停留在个人浏览，从未进入工作流。

附录用得好不好，检验标准很朴素：下次评审、下次复盘、下次选型会，这些页面有没有被真正打开过、引用过。一个只在刚读完时被翻动的附录，说明主线还没读完；一个被反复翻到卷边的附录，说明主线已经长在了读者身上。
