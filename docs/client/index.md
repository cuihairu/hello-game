# 8. 客户端架构与引擎体系

很多团队在服务端问题上容易进入“系统工程”视角，到了客户端却退回成“把 UI、角色和特效塞进引擎里”。这是一个很常见的误判。客户端并不是单纯的表现层，它本身就是一个长期运行的复杂系统，要同时承担输入、渲染、资源调度、脚本运行、网络交互、平台接入、性能适配、包体控制和版本演进。

客户端一旦复杂起来，很多线上问题都不再能简单归因为“美术资源太大”或“引擎不行”。真正暴露出来的通常是更硬的工程问题：

- 引擎能力和项目层架构到底怎么分工
- 哪些逻辑该放客户端，哪些必须交回服务端裁决
- 资源、代码、脚本和配置怎样一起组成可演进的运行时
- 性能、包体、热更和多端适配为什么经常互相拉扯
- AI 和自动化工具进入客户端链路后，边界和责任如何定义

这一章不是按引擎产品功能表来写，而是把客户端当成一套独立运行时系统来讨论。重点不在于某种技术是否“先进”，而在于它会把复杂度放到哪里，会如何影响版本节奏、团队协作和线上故障形态。
