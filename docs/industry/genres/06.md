# How to Use This Page

## Category

industry / genres subtree. Node positioning: the scope of use for genre topics — a genre can serve as a problem index, but cannot directly serve as an architecture answer.

## Definition


The correct way to use this set of appendices is to treat "game genre" as a quick index rather than as an architecture answer.

## Problem

Treating a genre topic as an architecture answer and copying it directly is the only wrong way to use this set of pages: the correct exit from a genre quick overview is to return to the problem models in the models subtree, where the six-question typology is the formal entry point for analysis.


### As an Entry Point into Project Problems

When project background is still unclear, a genre can serve as an initial index, helping narrow the search scope of the dominant pressures:

- Room-based products: first look at matchmaking, rooms, settlement, and reconnection
- Hard-real-time products: first look at the sync model, network quality, and anti-cheat
- Persistent online products: first look at server splitting and partitioning, state ownership, and operations capability
- Long-cycle progression products: first look at the asset model, event system, and data path
- Platform ecosystem products: first look at governance, review, permissions, and channel constraints

### Back to the Main-Line Problems

After building intuition, you must return to the main line and keep decomposing. What really should be asked is not "what kind of game is this" but the harder questions below:

- Where exactly does shared state live, and who has final interpretation rights
- Does time advance by frame, by event, or by transaction
- Where is the place where failure is least acceptable, and what is the recovery path
- Where do version updates and production operations push the complexity to
- Can the team's organizational capability and budget support the approach

Only when these questions are answered clearly does the genre judgment move from "looks like" to "can land."

### Finally, Remember One Fact

Many projects are not a single genre at all. A product can contain room combat, long-term cultivation, cross-server social play, and a UGC ecosystem at the same time. What truly dominates the architecture is usually not the genre label on the marketing page, but the most expensive, most fragile, and hardest-to-rollback path.

So this page is best suited for three things: quick comparison, organizing discussion, and retrospective summary. The one thing it is least suited for is replacing a complete design.
