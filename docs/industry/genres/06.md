# 如何使用这页

## Category

industry / genres 子树。节点定位：类型专题的使用说明——先建立直觉、再回主线问题、记住类型是索引不是答案。

## Definition


这一组附录的正确用法，是把“游戏类型”当成一个快速索引，而不是当成架构答案。

## Problem

把类型专题当架构答案直接抄，是这组页面唯一的错误用法：类型速览的正确出口是回到 models 子树的问题模型，六问分型才是正式分析入口。


### 先用它建立直觉

如果你刚接触一个项目，不知道该先看哪里，按品类切入是有效的。它能帮你迅速猜到主导压力大概落在哪：

- 房间制产品先看匹配、房间、结算和重连
- 强实时产品先看同步模型、网络质量和反作弊
- 持续在线产品先看分服分区、状态归属和运维能力
- 长周期成长产品先看资产模型、活动系统和数据链路
- 平台生态产品先看治理、审核、权限和渠道约束

### 再回到主线问题

建立完直觉以后，必须回到主线继续拆。真正该问的不是“这是哪一类游戏”，而是下面这些更硬的问题：

- 共享状态到底在哪里，谁有最终解释权
- 时间是按帧推进、按事件推进，还是按事务推进
- 故障最不能接受的地方是哪里，恢复链路是什么
- 版本更新和线上运营会把复杂度推到哪里
- 团队的组织能力和预算能不能支撑方案

只有这些问题答清楚，品类判断才会从“像”变成“能落地”。

### 最后记住一个事实

很多项目根本不是单一品类。一个产品可以同时包含房间战斗、长期养成、跨服社交和 UGC 生态。真正主导架构的，通常不是宣传页上的类型标签，而是最贵、最脆、最难回滚的那条链路。

所以这页最适合做三件事：快速对照、组织讨论、复盘归纳。它最不适合做的一件事，是替代完整设计。
