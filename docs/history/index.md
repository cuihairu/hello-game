# 游戏发展历史线

> 技术选型不是凭空来的：今天游戏服务端里的每一样东西，都是某个年代某款具体产品在具体约束下逼出来的答案。这条时间轴沿**八条线**回看 1970s 以来的游戏史：
>
> - **游戏发展**：标志性产品与品类的兴起；
> - **硬件**：PC/主机/手机与显卡世代的更替；
> - **前端技术**：Web 与浏览器图形接口的演进；
> - **后端技术**：数据、缓存、集群与并发模型的成型；
> - **知名引擎**：从引擎与游戏一体到授权生态的成型；
> - **玩法**：关卡、成长、多人与开放世界范式的演进；
> - **美术风格**：从像素到写实再到风格化的审美迁移；
> - **公司与代表作**：标志性公司及其代表作、开创了什么。
>
> 年份以公开资料中较通行的说法为准；细节存有争议或资料不一的，标注「约」。每个条目均遵守三硬字段约定：出现时的**硬件/环境条件**、**解决了什么问题**、**有哪些弊端**。轨道间的因果关系以「→ 催生 / ← 受影响」的互链徽标双向成对展示。

## 八轨交汇出的今天

把八条线叠在一起看，今天的格局大致是：

- **游戏与玩法**上，长线运营成为主流产品形态：版本管线、数据分析、运营安全不再是「上线后的事」，而是立项就要画进图纸的部分；
- **硬件与前端**上，移动 GPU 与浏览器 WebGPU 把「跨端同一套渲染」变成常态，服务端的裁决与客户端的表现力必须协同预算；
- **后端与引擎**上，商业引擎（Unreal、Unity、Godot 等开源新势力）与头部自研并行，引擎与客户端的分工、约束与协作边界见[第 03 讲](/24-game-types-architecture/03-frontend-engines)；同步模型则继续回答[第 04 讲](/24-game-types-architecture/04-network)的老问题：QuakeWorld 的预测插值，长成从接入、房间、到大世界的完整分层。

> 历史不会重复，但会押韵：每当平台（街机→主机→PC→网页→移动→云）与网络条件变化，同步模型与服务器架构都会被重新回答一遍。读历史，是为了在新约束出现时认出那些老问题。
