# 登录、支付、社交与广告 SDK

《登录、支付、社交与广告 SDK》讨论的是 平台与 SDK 里的一个关键切面。它真正关心的不是定义本身，而是这个切面如何改变系统边界、团队协作方式和线上故障形态。

## 问题从哪里来

平台不是中性的运行环境。它会带来审核规则、包体限制、接口差异、支付通道和商业化要求，这些都可能改变客户端、服务端和发布管线。

## 什么时候会变成主问题

跨平台发行、小游戏适配、多渠道登录支付和广告变现时，这类问题会在研发和运营两侧同时显现。

## 常见方案与取舍

常见做法是用适配层隔离 SDK、把平台能力抽象成项目内接口，再围绕版本、权限和失败补偿设计兜底链路。 围绕“登录、支付、社交与广告 SDK”做设计时，最好先明确目标链路、失败代价和观察指标，再决定复杂度应该放在哪一层。

## 常见误区

最常见的错误是让平台 SDK 直接侵入核心逻辑，或者忽略渠道差异导致测试和回归成本失控。 如果围绕“登录、支付、社交与广告 SDK”的讨论只停留在概念名词，而不落到状态归属、版本窗口和恢复方式上，方案通常会流于表面。
