# Design

## Category

Overview of the design tree. Node position: design-side knowledge is organized by problem domain — first the technical form of a type (problem model), then the crosswise quick reference (problem-domains); later design subdomains (gameplay design, levels, social, and so on) extend by the same pattern.

## Definition

The design side answers "what kind of problem is this": the industry/models subtree translates gameplay tags into six technical problem models and gives a typing method; the problem-domains subtree compresses the key judgments of the five problem domains into quick-reference pages. The technical trees (server/system/client and so on) answer "how is this problem solved"; the join point between the two layers is typing.
