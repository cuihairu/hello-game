# 成长曲线模型

## Category

numerical 树。节点定位：三条基础曲线、成本曲线（成长感=收益/成本）、战力当量化与分段节点——投入与能力兑换关系的骨架。

## Definition


成长曲线回答一个问题：玩家投入（时间、操作、付费）与角色能力（属性、战力）之间的兑换关系。它是长线游戏的骨架——成长太慢留不住人，太快则内容迅速贬值。本页给出三条基础曲线、成本与收益的配对方法，以及「成长感」的量化口径。

## Problem

成长曲线太慢留不住人、太快内容贬值，但「快慢」没有口径就无法讨论：必须落到收益/成本比值与战力当量化，成长感才可计算、可调参、可验收。


### 三条基础曲线

设等级为 n，能力值为 A(n)，基础值为 A₀：

- **线性**：A(n) = A₀ + a×n。每级绝对增量恒定，相对增量递减（100+50n：第 10 级涨 50，是 600 的 8%；第 100 级同样涨 50，只剩 5100 的 1%——绝对值稳定，成长感随等级衰减）
- **幂函数**：A(n) = A₀×n^b。介于线性与指数之间，b 越大后期越陡（b=1.5，A₀=100：10 级 3162、50 级 35355、100 级 100000）。大量 MMORPG 的属性成长落在这里
- **指数**：A(n) = A₀×r^(n−1)。每级按固定比例复利（r=1.1，A₀=100：10 级 236、50 级约 1.07 万、100 级约 125 万）。后期数字爆炸性增长，适合「数值狂欢」型挂机玩法，慎用于需要长期平衡的 PVP

三条曲线在同样的等级跨度下形态差异巨大——选曲线就是选游戏的长相：竞技对抗要平（可平衡），单机成长爽感要陡（可夸张），长线运营通常幂函数起步、用分段拟合控制每段的斜率。

### 成本曲线：成长感是「收益/成本」的比值

玩家感知的成长速度不是 A(n)，而是 **ΔA/ΔT**：每单位时间的属性增量。而 ΔT 由升级成本曲线决定（成本 C(n) = C₀×n^c 或分段手工调）。设计动作是两条曲线配对：收益曲线定形态、成本曲线调节奏——前期 c 要小（新手期几小时一级的成长脉冲），中期 c 抬升（给养成系统让位），大版本节点用新系统（新装备槽、新技能位）把 ΔA 突然拉高，制造「阶段感」。

**成长感的量化口径用相对增量**：+50 攻在攻击 100 时是 +50%，在攻击 1000 时是 +5%——同样的绝对值，体感差十倍。验收成长节奏时看百分比增量（每小时/每日/每版本战力提升百分比），而不是绝对值。

### 战力当量化

多属性系统需要一个**战力当量**把不同属性折算成单一数字（用于排行榜、战力门槛、成长汇报）。折算系数来自战斗模拟或公式推导：例如以「等效 DPS」为锚，1 点暴击率的价值 = 它带来的期望伤害增幅 × 基准攻击。当量化的两个纪律：**权重随版本复核**（数值膨胀会改变属性边际价值，权重不更新战力就失真）、**战力只做参考不做结算**（PVP 匹配、奖励门槛用战力分级可以，直接按战力判胜负不行——公式之外还有操作与克制）。

### 分段与节点

长线成长的实际形态几乎总是**分段函数**：每个资料片/大版本一段，段内用平滑曲线、段间用新系统跳变衔接。分段带来的管理成本是「段间对账」：新段开局时，老玩家与新玩家的相对位置（百分比差距）是否在可接受区间——这是合服、回流、赛季重置等运营动作的数值基础（运营侧对照第 14 章）。

### 常见误区

- **一条指数曲线跑到底**：百级之后数字大到失去意义，平衡与表面积都失控——长线游戏用分段控制
- **只调收益不调成本**：觉得升级慢就抬属性增量，其实调成本曲线更隐蔽也更可控
- **绝对增量验收**：「每级 +50」听着整齐，感知是递减的——成长感验收必须用相对增量
- **战力权重长期不更新**：版本更迭后战力排行榜与真实强度脱钩，玩家用脚投票
- **成长没有脉冲**：全程平滑等于全程平淡——阶段感来自设计好的跳变节点，而不是自然增长
