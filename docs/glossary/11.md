# 角色、实体与 MMO 空间术语

## Category

glossary 树节点。整理角色、分布式实体、空间和服务进程的英文名称，逐项给出中文含义、职责边界和可查来源。重点覆盖 BigWorld、KBEngine，并对照 Unreal、Unity 的不同用法；不把项目自定义类名包装成行业标准。

## Definition

读一个游戏服务器架构，应先分清四件事：业务上是什么对象、它有哪些分布式部分、模拟位于哪个空间分区、这些部分由哪个进程承载。同一个玩家角色可以有 Base 部分和 Cell 部分，但不是把完整资料复制两遍；同一个 Space 可以分配多个 Cell，也不是一份地图资源对应一个进程。

本文引用 BigWorld **2.1 的原厂文档存档**解释历史词义，引用 **14.4.1 源码存档**核对进程/空间结构，引用 KBEngine 官方文档与示例说明实现用法。版本和出处分开标注；旧版本对部署的限制不是所有引擎的通用约束。来源证明该项目怎样使用术语，不证明它首创该词，也不证明任意采用同名类型的项目已经实现相同能力。

## Problem

容易造成理解成本的不是英文名字长，而是把不同层次混成同一个东西：Avatar 等于 Cell 实体、Base 等于数据库、Cell 等于 CellApp、Instance 等于进程、Proxy 等于独立网关。另一个风险是根据常见单机体验推导服务生命周期：玩家不在线，不代表长期对象不能被激活；固定玩家身份，不代表固定承载进程。

## Algorithm

### 1. 先判断名字属于哪一层

| 层次 | 回答的问题 | 例子 |
|---|---|---|
| 业务对象 | 是账号、参与者还是一个可操控角色？ | Account、Player、Avatar、Character |
| 实体部分与权威 | 哪部分负责非空间业务，哪部分裁决模拟？ | Base entity、Cell entity、Real、Ghost |
| 运行空间 | 在哪个坐标空间、哪个分区，属于哪次活动？ | Space、Cell、Instance |
| 承载与管理进程 | 谁推进模拟，谁分配容量和归属？ | BaseApp、CellApp、CellAppMgr |

模块名、类名、二进制名可以有关联，但必须分别说明。相同二进制可以用参数启动不同进程角色；相同角色类名也可以在 Base、Cell 两个模块分别实现。

### 2. 角色、账号与客户端对象

| 原词 | 常用中文 | 含义与边界 | 来源 |
|---|---|---|---|
| Entity | 实体 | BigWorld 中可寻址的基本对象；业务类型决定属性和行为。不是只能表示玩家，也不等于数据库的一行。 | [BigWorld 2.1 词汇表](https://howarduong.github.io/github.io/doc/html/glossary_of_terms/glossary_of_terms.html)、[KBEngine 实体定义](https://kbengine.github.io/docs/programming/entitydef.html) |
| Avatar | 角色实体、化身 | BigWorld 词汇表允许玩家角色和 NPC；BigWorld 文档与 KBEngine 示例中的 Avatar 可以有 Base、Cell、客户端部分，不能限定为只存在于 CellApp。 | [BigWorld 词汇表](https://howarduong.github.io/github.io/doc/html/glossary_of_terms/glossary_of_terms.html)、[BigWorld 教程 §3.4](https://howarduong.github.io/github.io/doc/html/bigworld_tutorial/bigworld_tutorial.html)、[KBEngine Base Avatar](https://github.com/kbengine/kbengine_demos_assets/blob/master/scripts/base/Avatar.py)、[Cell Avatar](https://github.com/kbengine/kbengine_demos_assets/blob/master/scripts/cell/Avatar.py) |
| PC / NPC | 玩家角色 / 非玩家角色 | 区分角色由玩家还是游戏逻辑控制；不用于区分 Base/Cell，也不说明对象是否持久。 | [BigWorld 词汇表的 Avatar 项](https://howarduong.github.io/github.io/doc/html/glossary_of_terms/glossary_of_terms.html) |
| Account | 账号、账号实体 | KBEngine 示例承接账号入口、角色列表和选择；Account 与 Avatar 分开。具体游戏可以按需求组织，不要求所有项目必须支持多角色。 | [KBEngine Account 示例](https://github.com/kbengine/kbengine_demos_assets/blob/master/scripts/base/Account.py) |
| Player | 玩家、参与者 | 使用时须说明指真实用户、当前连接、所选角色还是引擎对象，不能只靠 Player 名字推导数据和生命周期。不同引擎没有统一的 Player 类。 | [Unreal Gameplay Framework](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-framework-in-unreal-engine)、[KBEngine 客户端接口](https://kbengine.github.io/docs/programming/clientsdkprogramming.html) |
| Pawn / Character | 可控制对象 / 角色 | Unreal 的 Pawn 是玩家或 AI 可控制的世界对象，Character 是带角色移动等能力的子类；不能直接当成 MMO 的 Base 对象。 | [Unreal 官方 Pawn](https://dev.epicgames.com/documentation/en-us/unreal-engine/pawn-in-unreal-engine) |
| PlayerController / PlayerState | 玩家控制器 / 玩家状态 | Unreal 把控制和玩家状态分开；PlayerState 并不天然提供跨区服长期资料归属、存储写权或离线订单处理。 | [Unreal Gameplay Framework](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-framework-in-unreal-engine) |
| Avatar（Unity 动画） | 人形动画骨骼映射 | Unity 配置后的 Avatar 为人形动画重定向提供标准骨骼层级和名称；与这里的分布式服务端角色对象不同。 | [Unity 官方重定向说明](https://docs.unity.com/en-us/engine/6000.6/manual/animation-section/animation-mecanim/avatar-creationand-setup/retargeting) |

### 3. Base、Cell 与远程调用

| 原词 | 常用中文 | 含义与边界 | 来源 |
|---|---|---|---|
| Base entity / Base part | 实体的 Base 部分、基础部分 | 承担非空间逻辑，与空间模拟部分分工；不是数据库进程，也不保证所有 Base 实体都持久。 | [BigWorld Base 源码，14.4.1](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/baseapp/base.hpp)、[KBEngine 属性作用域](https://kbengine.github.io/docs/programming/entitydef.html) |
| Cell entity / Cell part | 实体的 Cell 部分、空间模拟部分 | 推进位置和其他空间模拟；同一逻辑角色可同时具有 Base 部分，二者状态按权威划分。 | [BigWorld Cell Entity 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellapp/entity.hpp)、[KBEngine Cell Avatar](https://github.com/kbengine/kbengine_demos_assets/blob/master/scripts/cell/Avatar.py) |
| Real entity | 权威实体 | 分区中拥有模拟裁决权的实体形态；不是“拥有一个对象指针就能写”。 | [BigWorld Cell Entity 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellapp/entity.hpp) |
| Ghost entity | 非权威投影、影子实体 | 对权威实体的非权威表示，用于跨分区可见性等；不是第二个能独立发奖或修改资料的角色。迁移快照也不自动等于长期 Ghost。 | [BigWorld 词汇表](https://howarduong.github.io/github.io/doc/html/glossary_of_terms/glossary_of_terms.html)、[Cell Entity 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellapp/entity.hpp) |
| Witness | 观察者视图上下文 | BigWorld 负责客户端观察相关的实体/可见性上下文；与 Ghost 的跨分区副本含义不同。 | [BigWorld Witness 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellapp/witness.hpp) |
| Proxy | 带客户端关联能力的 Base 实体 | BigWorld/KBEngine 示例的玩家 Base 部分可以继承 Proxy；不是所有 Base 实体都有客户端，也不能与独立 gateway 一一等同。 | [BigWorld Proxy 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/baseapp/proxy.hpp)、[KBEngine Base Avatar](https://github.com/kbengine/kbengine_demos_assets/blob/master/scripts/base/Avatar.py) |
| Mailbox / EntityCall | 实体远程调用引用 | 跨部分/进程访问实体的方法引用，而非共享指针；两项目的具体实现不同，不假定引用永久固定某个 IP。 | [BigWorld Base 源码中的 mailbox](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/baseapp/base.hpp)、[KBEngine EntityCall 源码](https://github.com/kbengine/kbengine/blob/master/kbe/src/lib/entitydef/entity_call.h) |

Base/Cell 表达职责拆分，能否动态迁移 Base 是具体版本和项目能力。BigWorld 2.1 词汇表描述过 Base 固定位置的模型，不能把它推广为“行业所有 Base 永不迁移”，也不能反过来假设引擎已自动支持 Base 负载迁移。

### 4. 地图、空间与玩法生命周期

| 原词 | 常用中文 | 含义与边界 | 来源 |
|---|---|---|---|
| Map resource | 地图资源 | 静态资源，与一次运行空间和玩法活动分开；同一地图可以被多次使用。 | [BigWorld 教程的资源与 Space 示例](https://howarduong.github.io/github.io/doc/html/bigworld_tutorial/bigworld_tutorial.html) |
| Space | 运行空间 | BigWorld 的空间身份和坐标上下文，管理 Cell 集合；不是静态地图文件或某个进程。 | [BigWorld Space 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellappmgr/space.hpp) |
| Cell | 空间分区 | Space 中的一块空间范围及其本地模拟；不能与承载它的 CellApp 进程混用。 | [BigWorld Cell 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellapp/cell.hpp) |
| Scene | 场景 | 名字本身不能确定是资源场景、运行容器还是玩法。Unity Scene 与 BigWorld Space 有各自引擎边界，项目必须写明对应关系。 | [Unity Scenes 手册](https://docs.unity3d.com/6000.0/Documentation/Manual/CreatingScenes.html)、[BigWorld Space 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellappmgr/space.hpp) |
| Instance / Dungeon instance | 运行实例 / 副本实例 | Instance 是复用词，应明确实例化的对象。副本玩法可以关联独立 Space，但具体阶段、结算和销毁规则属于玩法；Unreal GameInstance 则是另一种引擎生命周期对象。 | [Unreal Gameplay Framework 的 Game Instance](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-framework-in-unreal-engine)、[Blizzard 对跨阵营 instances 的说明](https://news.blizzard.com/en-us/article/23796742/shadowlands-a-look-at-cross-faction-instances) |

典型关系是：地图资源供 Space 使用，Space 的模拟由一个或多个 Cell 承担，CellApp 承载这些 Cell。一次副本玩法可以关联 Space，但不能仅凭“Instance”一词推导“一副本一进程”。单 Cell 空间也不意味着已经具备切分、Ghost、跨边界战斗和无缝迁移。

### 5. 承载进程、管理进程与外部接入

| 原词 | 职责 | 容易混淆的边界 | 来源 |
|---|---|---|---|
| BaseApp | 承载 Base 实体 | 实体不等于进程；一个进程可承载多个业务对象。 | [BigWorld Base 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/baseapp/base.hpp) |
| CellApp | 承载空间模拟与 Cell | 不等于一个 Cell，也不等于一个副本活动。 | [BigWorld CellApp 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellapp/cellapp.hpp) |
| BaseAppMgr / CellAppMgr | 管理相应承载进程及分配 | 管理面不因掌握拓扑就成为每个实体的模拟者。 | [BaseAppMgr](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/baseappmgr/baseappmgr.hpp)、[CellAppMgr](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/cellappmgr/cellappmgr.hpp) |
| DBApp / DBMgr | 引擎中的存储及相关协调职责 | 名称和职责随版本不同，不与外部 MySQL 服务端或纯存储代理自动等同。 | [BigWorld DBApp 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/main/programming/bigworld/server/dbapp/dbapp.hpp)、[KBEngine DBMgr 源码](https://github.com/kbengine/kbengine/blob/master/kbe/src/server/dbmgr/dbmgr.h) |
| interfaces（KBEngine） | 第三方账号、登录、计费接入 | 与客户端长连接入口不同；也不是每个游戏必须部署的行业标准组件。 | [KBEngine 官方配置](https://kbengine.github.io/cn/docs/installation.html)、[interfaces 源码](https://github.com/kbengine/kbengine/blob/master/kbe/src/server/tools/interfaces/interfaces.cpp) |

| bwmachined / machine | 本机服务发现、启动与监督等引擎能力 | 具体引擎可能有额外职责；项目只借用本机监督部分时，应明确限制，不能据名字推导跨服业务调度。 | [BigWorld machine daemon 源码](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/tree/main/programming/bigworld/server/tools/bwmachined)、[KBEngine machine 源码](https://github.com/kbengine/kbengine/tree/master/kbe/src/server/machine) |

### 6. 名字相同，不代表同一生命周期

以采用 Base/Cell 拆分的项目为例，以下是设计检查项，不是宣称所有引擎默认提供这些能力：

1. 客户端登录建立认证会话，角色 Base 部分的加载/激活是另一件事；离线业务也可以按项目设计触发激活。
2. 进入玩法创建或关联 Cell 部分，离场销毁模拟对象，不必卸载长期资料。
3. 玩家角色身份应稳定，当前 Base/Cell 承载地址是可变路由；支持迁移的系统须交接写权、在途业务和版本，不能只改 IP。
4. 异步订单绑定稳定玩家/角色身份，不永久绑定 Base 进程。迁移或离线期间保留持久待办，按当前归属解析和投递。
5. 业务落账、通知已收到、模拟已执行是不同确认；重复支付通知不能重复发货，旧模拟源不能因缓存地址继续写入。

机制展开见[服务发现、路由与协作](/server/services/04)、[一致性、恢复与重连](/server/services/05)、[交易、支付与经济系统](/system/services/03)。KBEngine 的常规 charge 路径另有一个可核查细节：BaseApp 经 DBMgr 请求 interfaces，保存订单关联后再沿 DBMgr 返回发起方，并非 interfaces 先维护一份全量玩家到 Base 映射；这段内存请求关联也不保证跨重启支付恢复。[interfaces 请求/回执源码](https://github.com/kbengine/kbengine/blob/master/kbe/src/server/tools/interfaces/interfaces.cpp#L717)、[DBMgr 转发源码](https://github.com/kbengine/kbengine/blob/master/kbe/src/server/dbmgr/interfaces_handler.cpp#L544)

### 7. 命名判断的方法

先说明对象、权威、位置和承载，再选名称。若一个项目只实现玩家 Cell 部分，Avatar 并非不能使用，但必须说明范围；若长期对象另叫 Anchor 等项目名称，应列出现有类型与 Base/Cell 职责的对应关系，不把名字写成行业定义。

按 Base/Cell 模块分别实现同名 Avatar 可以表达同一角色的不同部分，这是沿用模型后的代码组织选择；不是行业强制的 C++ 命名空间，也不自动获得跨进程实体调用和迁移能力。通用知识库只记录可核查语义，各项目的具体命名和代码迁移保留在项目自己的设计件及任务中。
