# 调研总览

## Category

research 树根。节点定位：三份维度调研与一份差异汇总的入口，回答「本仓的知识面被外部材料复核过没有、复核结果如何」。判定口径与[玩法品类与功能组件覆盖对照](/system/genre-coverage)一致：只认独立篇与专节，正文出现一次词不算覆盖。

## Definition

调研分三个维度、一次汇总：**书籍维度**把公开出版的工程书当主题清单，逐本抽出「这本书回答什么问题」；**官方文档维度**把成熟引擎与中间件的官方文档当能力清单，逐份抽出「这份文档解决什么问题」；**应用场景维度**把抽出的主题放回品类里，回答「哪个主题在哪类游戏上吃紧」；**覆盖差异表**把三个维度的判定并成一本账，给出差异去向。三个维度相互独立，独立算出同一批缺口，是这套口径可信的依据。

## Problem

调研最容易变成「读过就散」：单篇里结论清楚，合起来看不出全貌，后来者要么重复调研，要么不知道哪份结论还成立。本页只做入口与索引，判定细节留在各篇，避免同一结论在两处维护。

## Related

关系链：三个维度独立调研 → 差异汇总 → 缺口排序 → 补齐与回核。逐段回答「为什么需要下一个」：

- 单一维度的清单给不出全貌，先要三个维度各自独立判定，本页表格承担这一层。
- 三个维度的判定并账之后，差异去向才清楚，见[覆盖差异表](/research/04-coverage-diff)。
- 差异表给出缺口顺序之后，补齐落点回到 system 树，入口是[系统总览](/system/)；知识侧收拢见[调研知识点总览](/knowledge)。

上游对照基准：[玩法品类与功能组件覆盖对照](/system/genre-coverage)。下游：[调研知识点总览](/knowledge)（把调研产出收成知识点与坑）。
