# 应用场景对照

## Category

research / 调研三。节点定位：把调研抽出的主题放回具体玩法品类里，回答「哪个主题在哪类游戏上吃紧」。品类清单、组件需求与判定全部引用[玩法品类与功能组件覆盖对照](/system/genre-coverage)的 21 个品类，本页不另立品类口径，只补「调研主题 → 品类 → 场景」这一层。

## Definition

同一主题在不同品类上的重量差一个数量级：任务进度对三消是三行配置，对 MMORPG 是全部内容量；语音对棋牌无所谓，对派对是标配。所以缺口排序不能按实现难度排，要按品类需求密度排，这一点[覆盖对照页](/system/genre-coverage)的缺口清单已经给过一次顺序，本页用品类视角复核它。

## Problem

调研本身只回答「有没有」，不回答「先写哪个」。写知识库时如果按调研顺序补，会先补上引擎细节这类到处都能查到的东西，而把签到、走马灯这种「运营一开活动就要、全网又没有现成文章」的件留在最后。本页按品类过一遍，得到的顺序与覆盖对照页一致，两处独立算出同一顺序，说明这个排序不是拍出来的。

## 按主题回看品类

- **任务与成就**：内容量越大越吃紧。MMORPG 的主线支线、卡牌的日常周常、回合制 RPG 的剧情任务，底层是同一套「定义表 + 事件推进 + 一次性发奖」，所以写一篇就够三个品类用，不必按品类分篇。
- **体力与次数门控**：节奏闸门。三消按体力限次、ARPG 按副本次数限次、塔防加一个扫荡，差别只在恢复速率与重置口径，主体是同一套按服务器日重置的幂等逻辑。
- **家园与领地**：空间归谁、谁能改、破坏怎么算。SLG 是领地归属，模拟经营是家园存档，生存建造是反破坏，三者共用空间底座与权限位，差别在规则层。
- **签到、兑换码与赛季通行证**：运营节奏件，休闲与放置最重。这三个件在活动开起来之后第一周就会被要，属于「不做就上不了线」型。
- **语音与游戏内公告**：下行通道。语音要接第三方 SDK，公告要在业务层做频控与保序，两者都跨了客户端与服务端，单独成篇才说得清边界。
- **外观与皮肤**：MOBA 与二次元的主力付费件，库存归属、穿脱权威、局内可见三件事夹在实体表现与同步之间。
- **装备强化与升星**：塔防与养成类的资源黑洞，失败保护与材料回收是事故高发点，概率口径与[掉落与概率设计](/numerical/05)共用。

## 已覆盖主题的品类分布

同步与裁决（MOBA、FPS、格斗）、匹配与段位（竞技类全部）、AOI 与分片（MMORPG、沙盒、RTS）、支付与对账（全部）、抽卡保底（卡牌、二次元、放置）这几组在对照页全部判定已覆盖，本次调研的书籍与文档维度也没有发现新问题，两侧互证：写得厚的地方外部材料对得上，写得薄的地方外部材料也指向同一批缺口。
