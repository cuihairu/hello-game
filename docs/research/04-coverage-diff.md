# 覆盖差异表

## Category

research / 调研四。节点定位：把书籍、官方文档、功能组件三个维度的判定并成一本账，给出差异去向与补齐结果。三个维度的原始判定分别在[权威书籍调研](/research/01-authoritative-books)、[引擎与中间件官方文档调研](/research/02-engine-middleware-docs)、[玩法品类与功能组件覆盖对照](/system/genre-coverage)，本页只做合并、不重判。

## Definition

覆盖差异 = 外部材料列出的主题与组件，对本仓 `docs/` 现有篇目的判定差额。三个维度的计数单位不同，不能相加：书籍与文档维度以「主题」计，功能组件维度以「组件」计，同一件事在三个维度里各记一次是设计如此，不是重复。

## Problem

三个维度分开看时，每篇都自洽，合起来才看得出两件事：一是「两侧互证」——写得厚的树外部材料对得上，写得薄的树外部材料也指向同一批缺口；二是差异去向——判定为「部分」的不补篇要给出理由，判定为「缺口」的要给出落点与顺序。没有这层合并，调研结论就只能停留在各篇内部。

### 判定为「缺口」的 11 项：已按需求密度补齐

11 项功能组件缺口（任务、成就、图鉴、装备强化升星、体力门控、签到福利兑换码、战令、走马灯公告、外观皮肤、家园领地、语音）由 2026-10-09 至 2026-10-10 的玩法系统丰富批十篇补齐，逐项落点与判定翻转见[覆盖对照页的缺口清单节](/system/genre-coverage)。补齐顺序按品类需求密度排（任务与成就最先，走马灯与签到其次），该顺序由[应用场景对照](/research/03-application-scenarios)与覆盖对照页两处独立算出、结果一致。

## Related

关系链：三个维度判定 → 并账 → 差异去向 → 补齐与回核。逐段回答「为什么需要下一个」：

- 各维度判定自洽但不成账，先要合并，本页的判定表承担这一层。
- 并账之后差异去向才清楚：部分项给不补的理由，缺口项给顺序与落点。
- 落点建好之后要回核，回核结果写回[覆盖对照页](/system/genre-coverage)的判定列，本页不重复维护。
